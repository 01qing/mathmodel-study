# Source Governance

本 Skill 的研赛知识库不采用“搜到什么就相信什么”的策略。

## 1. 来源等级

### primary_official
竞赛组委会、官方管理平台、命题/答疑官方渠道。

用途：
- 题目名称
- 赛题发布
- 比赛规则
- 正式更正
- 获奖名单

### repository_mirror
公开 GitHub 等对原题、附件、优秀论文的镜像。

用途：
- 获取可重复下载的题目、数据与论文
- 建立 SHA / 文件索引

注意：
镜像文件名可能存在错误，不能覆盖官方或题面正文。

### expert_or_author_material
参赛者、获奖者、命题相关专家的公开解析、代码、复盘。

用途：
- 学习解题思路
- 代码复现
- 方法比较

不能自动视为标准答案。

### secondary_index
数模网站、论坛、汇总页等二级索引。

用途：
- 补充导航
- 查找专家答疑
- 发现资料

不能单独用于解决来源冲突。

## 2. 冲突处理

一旦两个来源对同一事实冲突：

1. 不静默覆盖。
2. 建立 `conflicts[]`。
3. 保存各来源的原始说法。
4. 区分：
   - 页面标题/文件名
   - 题面正文
   - 数据语义
   - 后续作者解释
5. 若无法消除冲突，状态保持 `unresolved`。
6. 建模时使用与题面正文、变量和数据一致的任务语义，并明确记录冲突不影响哪些数学任务。

## 3. 奖项处理

“优秀论文目录”“作者自述一等奖”“博客称获奖”不是同一证据等级。

字段：
- `award_claim`
- `award_verified`
- `award_source_id`

只有可靠获奖名单能把 `award_verified` 设为 true。

## 4. 文件与来源分开

安装 Skill 时只携带元数据目录，不把几百篇 PDF/XLSX 打包进 `.agents/skills/`。

真实资料放：

```text
learning_sources/competitions/<year>/<problem_id>/
```

Skill 内的 `assets/catalog/` 只保存：
- 路径
- URL
- SHA（已知时）
- 文件类型
- 来源等级
- 验证状态
- 缺口

## 5. 2021 D 的示例冲突

当前已发现：
- 官方竞赛发布页使用“抗胰腺癌候选药物的优化建模”
- 一个公开数模题目索引使用“抗乳腺癌候选药物的优化建模”
- GitHub 镜像题面文件名使用“抗胰腺癌…”
- 题目相关数据与公开解析围绕 ERα 和乳腺癌语义

因此案例名称不得在未核清题面正文前被强制统一。
案例 manifest 使用中性名称：
`2021 D 候选药物优化建模`
并保存 title variants。
