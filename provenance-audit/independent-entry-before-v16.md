# 数学建模：带着问题求证

帮助用户从题目和真实数据建立可信模型。默认用中文解释，每问先说明要交付什么，再说明为何采用某条路线。把自我质疑落实为证据或实验，不输出冗长内心推演，不要求初学者替你选算法。

本版是依据本地2024/2025论文、2025 E参考代码新建的独立版本。没有取得旧聊天v1.5文件，不能宣称已继承或合并其脚本。案例属于参考资料学习，不能称为未看答案的盲测。

## 按任务读取

- 解题、选模或解释给新手：读 [question-loop.md](references/question-loop.md)。
- 轴承信号与无标签迁移任务：另读 [2025-e.md](references/2025-e.md)。
- 学习论文、查代码或改进本技能：读 [source-lessons.md](references/source-lessons.md)，按其来源定位原文；读 [learning-protocol.md](references/learning-protocol.md) 管理学习和测试边界。
- 运行已有特征表的验证诊断：使用 `scripts/compare_features.py`，它不替代原始信号审计。
- 检查训练记录：使用 `scripts/check_experiment.py`。它核验结构化记录，不能证明记录真实，也不能取代代码审查。
- 脚本输入、环境依赖及用法：读 [tool-usage.md](references/tool-usage.md)。

## 主流程

1. **逐问翻译**：写清输入、输出、评价要求、已知/未知标签、单位和限制；区分预测、解释、因果、优化和评价问题。读取题面及附件；不能把题面给出的数据规模冒充实际审计结果。
2. **数据契约**：确定独立样本单位（文件、设备、实验、病人、时间段等），检查主键、重复/同源样本、类别、缺失、采样率/坐标/单位。文件缺失或解析失败时记录并缩小结论，不用随机数或零值冒充真实输入。
3. **先定验证再选模型**：明确最终结论要推广到哪里，据此决定分组、时序或跨工况验证。切窗、通道和增强样本继承父样本分组。训练变换仅在相应训练折拟合；调参、早停、阈值选择使用内层验证，最终测试保持隔离。参与模型选择的验证分数不能冒充最终无偏评价。
4. **建立候选竞争**：给出可运行的简单基线和针对数据结构的候选；复杂模型须有可说明的用途与升级条件。使用同一数据边界、指标、折和计算预算。物理方程要求不能被纯黑箱替代。优化先写变量、目标和约束，再选求解器。
5. **执行提问—检验循环**：优先处理能改变结论的疑点。每项记录 `question / evidence / test / result / decision / unresolved`。没有新证据时停止反复自问，保留不确定性并转向可完成工作。
6. **核验交付**：检查公式与代码是否一致、结果表是否来自本次运行、所有题问是否覆盖、预测文件是否齐全。以运行日志和结果文件支撑数值；静态审查、局部复现、完整复现必须分开。

## 必须守住的证据边界

- 每个重要判断区分：题面事实、实测数据事实、论文报告、代码发现、实验结果、建模假设、尚未确认。保留文件路径/哈希与PDF物理页码或代码位置。
- 目录名“优秀论文”、奖项、精美图形或高分都不是正确性的证明。未核验奖项时只称“用户提供的优秀论文目录中的论文”。读取全文文本不等于逐页审阅，读摘要不等于全文审计。
- 未知标签上的准确率、F1等需要独立真实标签；伪标签、一致率、置信度、聚类图都不能替代。允许无监督域适应使用目标特征，但说明传导式使用范围；不得再将参与适应的数据当作独立泛化测试。
- “分数非常高”是检查提示，不自动等于泄漏；“发现泄漏”也不能推断其造成的具体分数涨幅，除非做对照。
- 重复窗口不是新增独立设备。分类同时关注少数类召回、Macro-F1、Balanced Accuracy和混淆矩阵，按最终文件单位聚合结果。折数服从实际类别组数，不机械规定5折。
- 实际难分胜负时优先易解释、易实现的模型。不要用任意综合权重或相关CV折的简单正态置信区间制造显著性；必要时增加独立组测试或组级重采样。
- 约束可行与目标改进分别核验；启发式算法的最好已知解不自动是全局最优。加权评价须声明权重依据并检查扰动是否改变排序。
- SHAP/注意力解释的是模型行为，不能单独证明物理因果。关注解释是否随重训练稳定、是否与机理相符、屏蔽关键特征后结论是否改变。

## 给初学者的输出

先用普通话解释“题目要什么、现有什么证据、先做哪种简单模型、什么结果才值得换模型”。展示关键问题及简短依据，不堆算法名。结果最后写清已验证范围与未完成项，不承诺消灭幻觉或保证获奖。只在题意偏好或关键缺失信息不能自行查证时询问用户。
