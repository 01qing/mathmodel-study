# 分组评估与未来迁移

当前45篇来自12道题。相同年份/题号的所有论文作为一个组，不随机拆论文：训练8组32篇，开发2组7篇，测试2组6篇。训练：2024 A/B/C/E、2025 A/C/E/F；开发：2024 D、2025 B；测试：2024 F、2025 D。

这只是预先声明的一次结构覆盖划分，不是统计上唯一最优划分。测试题型与训练题型不同，挑战在局部结构迁移；样本很少，不能根据这一次分组报告普适的正确率。

## 两个不同阶段

开发时只用train库拟合词频与建立候选。dev用于完善查询表达和评审标准。冻结检索代码、库、查询与适用性判据的哈希，再使用test题面查询训练库。需要原题时读官方题面，不能把测试论文的算法答案直接拼成查询；从测试论文生成的查询只能称回溯自测。

所有评估结束后，可把45篇都纳入正式检索库。用户希望全量学习与留出评估可以先后进行，但全量学习后的45篇不能再拿来证明未见题目的能力。今后的干净盲测需要未接触解法的新年份/新案例和隔离输入。

## 判什么

逐问检查：引用论文/页码是否真实；相似部位是否定位正确；关键不适用条件是否指出；是否给出有效迁移方案；无可用匹配时是否敢于不匹配。可用人工标注相关项计算Recall@k/MRR，但没有独立标注时不编造这些指标。文件格式、搜索能返回结果和引用能回读仅是工程测试。

至少加入反例：同算法但目标不同、同领域但标签条件不同、同为优化但可行域不同、主观评分被当成真值、源域高分被迁移到无标签目标。相关性标签与可迁移性标签分开；“相关”不等于“可照搬”。

## 扩展顺序

先局部方法检索与差异审查，再加入跨论文组合路线、反面案例、计算预算建议和不确定性传播。允许每问从不同论文借鉴子步骤，但必须校验接口、变量、单位及误差传播；不能把几个算法拼起来就称创新。
人工/Agent修正要留下证据和版本，不自动把用户采纳当成模型正确。后来失败的案例应能降低方法卡的适用范围，而不是只积累成功例子。
