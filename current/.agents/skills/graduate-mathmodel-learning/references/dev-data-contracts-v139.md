# v1.39 数据合同审计增量

来源为Dev调优，只有通用诊断规则进入Core。论文特定阈值、地名、结果和选线不进入Train检索。与已有v1.13实体、v1.17/18 schema和类别门禁、统一Result Registry联用，不另复制同义规则。

1. 对实体-时间表先验证唯一键，再声明连接基数，检查连接前后行数。静态表先扩年后连接时，不能丢失年份。窗口长度应由日期/年度轴定义，不能默认DataFrame三行等于三年。
2. 时间支持必须追到文件选择器和聚合算子：单日不能因列名改变而成为年均；未来地区输出必须有相应地区输入或明确空间分解模型。相同完整输入进入同一确定性模型，输出应相同。
3. 图中的类别名称从拟合encoder及model.classes_派生；按具体代码分支核验。存在正确的另一分支时，不把局部错误推广为全部错误。
4. 指标比较登记target、statistic、importance_type、normalization、run_id、input_version。分裂次数与gain、预测值与空间自相关统计量不直接比较；不同口径先判不可比较，不自动判数值错误。
5. 自构指数的阈值标签只允许评价指数模仿。真实结果标签及来源另行登记；没有独立观测就不能把准确率表述为真实成灾/损失预测能力。
6. 空间摘要分开保存sum(area×fraction)与加权中心/协方差。整体权重翻倍应使总量翻倍而不改变归一化协方差；椭圆范围面积不能代替资源总面积。
7. 椭圆概率覆盖声明须给维数、尺度和分布前提或经验覆盖验证。描述性协方差不必假设正态；一维覆盖率KDE不能证明二维坐标联合正态。一维68%规则不能直接解释二维椭圆。

算法推荐门槛保持Baseline-first；以上审计修复不是复杂模型提升证据。作者可执行链缺失仍保留R2边界。解释稳定性和下游用途实验尚未完成，不因规则发布而改记PASS。
