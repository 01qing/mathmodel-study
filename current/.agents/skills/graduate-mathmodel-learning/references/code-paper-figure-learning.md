# 论文、代码、图表与论证联合学习协议

本协议用于处理“论文 + 附录代码 + 作者代码包 + 结果图/表”案例。目标不是收集算法名，而是形成可迁移的完整链：题目要求 → 数据 → 数学模型 → 代码实现 → 图表证据 → 论文结论。

## 1. 来源与身份

每个论文、代码包、结果文件必须分别登记来源、SHA256 和身份。专家/教师资料属于 `expert_or_author_material`，可以训练解题和复现能力，但不能冒充优秀论文、官方答案或测试真值。同一题的补充代码只能并入其所属 split；不得因新增代码改变 train/dev/test 分组。

## 2. 五层核验状态

代码案例至少区分：

1. `indexed`：文件已发现并登记。
2. `syntax_checked`：Python 等可静态解析，不能据此声称可运行。
3. `smoke_runnable`：入口/帮助或最小样例实际执行成功。
4. `partial_reproduction`：用真实或明确标注的样例数据得到可检查输出。
5. `full_reproduction`：从题目原始数据到论文主要数值/图表链完整复现。

不得用低层状态代替高层状态。缺原始数据、依赖、环境或路径时明确记录阻塞项。

## 3. 代码静态审计

先运行 `scripts/audit_code_bundle.py`，再人工核看关键入口。至少检查：

- Python 语法、主要 imports、CLI 入口；
- 数据文件名、绝对路径、模型权重和中间产物依赖；
- 数据划分单位是行、窗口、文件、对象还是时间段；
- 缩放、PCA、特征选择、过采样等是否在划分前拟合；
- 随机种子、类别映射、缺失输入处理、采样率和单位；
- 输出数值、表格、图像分别由哪个函数/脚本产生；
- 论文公式与代码运算符、归一化、聚合口径是否一致。

静态脚本只发现线索，不自动判定科学正确性。

## 4. 实际运行

优先顺序：

1. 原作者入口 + 原始题目数据；
2. 原作者入口 + 作者随包样例；
3. 修正路径/文件名后的同一代码；
4. 我们的最小重实现；
5. 合成/代理数据烟测。

每次运行保存：输入身份、命令、依赖、随机种子、stdout/stderr、数值结果和图表。修正路径、变量名或公式时必须另存，不覆盖作者原件。

## 5. 论文到代码映射

按每一问建立映射表：

`题目子问 → 论文公式/步骤 → 代码文件 → 函数/类 → 输入 → 输出 → 图/表 → 结论`。

无法映射时标记 `paper_code_gap`。代码出现论文未说明的重要处理时标记 `undocumented_code_step`。论文声称存在但代码包没有对应实现时标记 `missing_implementation`。

## 6. 图表学习

每张图记录：

- 图类型和面板数；
- 输入数据与生成代码；
- 横纵轴、单位、尺度、图例、标注；
- 尺寸比例、子图布局、字体、线宽、网格、颜色、留白；
- 它证明的命题；
- 它不能证明的命题；
- 对新题可迁移的是“证据结构”还是仅视觉风格。

学习构图时优先复制证据逻辑，不盲目复制配色或图数。例如：两次预测与融合的分组柱状图能展示逐样本变化；两次置信度散点配 `y=x` 能展示两次运行一致性；标签数量柱状图只能展示预测分布，不能证明分类正确。

## 7. 新题检索返回代码链

若相似案例具有已审计代码，检索回答除论文页码外应增加：

- 可借鉴的具体代码阶段/函数；
- 需要重新匹配的数据接口和单位；
- 推荐复用的图表证据结构；
- 最小可运行基线；
- 已知 bug/泄漏/失效条件；
- 什么结果会让我们放弃这条迁移路线。

不能因为代码更完整就自动提高模型推荐优先级。

## 8. 测试组隔离

冻结 Skill 后做测试题时，不读取测试论文及其附录代码、结果图、作者参数和作者选图方式。测试答案、代码、图片、全文论证冻结并哈希后，才能打开测试材料做比较。测试后学到的新规则必须进入新版本。
