# 2024-D 冻结独立解答 vs S013–S016 Dev Gap Analysis

## 证据顺序

独立解答在 2026-09-11 已以 v1.38 frozen solver、官方题面和官方数据先行冻结，freeze manifest 标记 `INDEPENDENT_SOLUTION_FROZEN`。S013–S016 的阅读发生在冻结之后。本文只比较能力缺口和通用规则，不追改冻结答案，也不把 Dev 的具体参数写进 Train retrieval。

## 独立解答做对的部分

1. **问题边界较稳**：Q1 将年累计、面积权重、土地份额和缺测端点显式区分；四篇论文的统计名称/实现漂移反而验证了这类合同的重要性。
2. **复杂模型没有自动升级**：Q2 预注册了开发 MAE + 5 个空间折门槛，复杂候选未达门槛时保留 climatology。S013–S016 的不同目标/随机切分/低解释力/标签泄漏等发现支持这一“Baseline-first”策略。
3. **Q3 对证据范围较诚实**：没有灾害真值和排水能力时只给条件情景，不把自造阈值、伪标签或未来地图写成校准概率。四篇 Dev 多次暴露这类证据扩大风险。
4. **Q4 将结构描述和政策效用分开**：PCA/KMeans 只承担低维结构与重建/稳定性，未把聚类直接写成用途收益。

## 独立解答暴露的能力缺口

1. **Q1 的稳健趋势/统计不确定性不足**：冻结方案主要给 OLS 描述趋势，没有预注册 MK/Sen、块 bootstrap 或异常年份敏感性。Dev 论文提示应将稳健趋势作为条件模块，但不能因论文使用就默认升级。
2. **Q2 “交互规律”解释弱**：独立解答的候选主要以预测 MAE 竞争，虽然避免过拟合，但对地形×温度交互的可解释稳定性、稀有事件校准和尾部错误分析仍不足。应增加分块交互方向/阈值稳定性与少数事件指标。
3. **Q3 缺少统一标签谱系对象**：虽然文字上区分条件情景和灾害概率，但没有系统保存 `label_source / forecast_origin / available_at / prediction_scope`。S015/S016 显示这是高频失败点，应成为通用 schema/检查门禁。
4. **Q4 缺少“组成边际≠转移流量”的显式可识别性门禁**：冻结解答没有误用流量，但规则层尚未把这件事写成主动检查；S016 证明仅凭份额边际无法唯一恢复真实转移矩阵。
5. **跨程序/中间文件 provenance 仍可加强**：A题复盘与 S016 均表明，源文件 hash 不能替代实际被求解器读取的转换后文件。v1.41 保留该问题为运行账本强化方向；没有真实生产链集成回归的 A题候选不单独宣称已验证。

## 规则更新决定

允许写回 Core 的只有通用门禁：统计对象与分母同源、重采样与目标总体分离、标签谱系与预测可用性、评价机制(fitted/OOB/holdout)分离、未来图≠回测、组成边际≠流量、output_space/class/link 明确、tail/operator/坐标/header 跨接口核验。

不写回 Core：四篇论文的具体阈值、AHP权重、聚类数量、2025–2035风险排名、作者未来地图、未复现模型参数和不同目标间的分数排行榜。

## 能力结论

这是一个合法的 Dev gap analysis：它证明 v1.38 独立答案具有若干可靠决策，也暴露可改进的通用门禁。它**不能**证明 v1.41 比 v1.40 或 No-Core 更强；Controlled Core Ablation 仍为 `NOT_RUN`。
